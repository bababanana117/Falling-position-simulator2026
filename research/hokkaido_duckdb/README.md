# 北海道 高層風 統計データベース

JRA-3Q 再解析の 2016--2025 年から、北海道周辺の上空の風を集計した DuckDB
ファイルです。緯度・経度・気圧面・高度・時期を指定すると、風速と風向の統計値が
返ります。風速と風向には確率分布を当てはめてあり、関数形と定数が表に入っている
ので、落下位置のモンテカルロ計算にそのまま渡せます。

> 見てください。

## 使い方は PDF にあります

このディレクトリの説明はすべて `docs/` の Sphinx 文書にあります。README には
書きません。

PDF は同梱しています。作り直すときは `docs/requirements.txt` を入れてから
次を実行してください。

```bash
make -C docs            # doctest → HTML → PDF
```

できあがるもの:

| 出力 | 場所 |
|---|---|
| PDF（83 ページ） | `docs/hokkaido-wind-duckdb.pdf` |
| HTML | `docs/_build/html/index.html` |

手引の構成は、まず動かす / データの構造 / **取扱上の注意** / 分布の定義 /
使い方の例 / 表と列の一覧 / 再現の手順 / ライセンス / 用語集 です。
数字を読み違えやすいところは「取扱上の注意」にまとめてあります。

## データベースを作り直す

読むだけなら `duckdb` だけで足ります。作り直すには、このアーカイブに**入って
いない**ものが 2 つ要ります。

1. JRA-3Q の 6 時間ごとの解析値（NSF NCAR GDEX の `d640000` から取得）
2. それを半月ビンに集計する上流のパイプライン

その 2 つが揃っていれば、`hokduck` を取り込める場所に置いて次を実行します。

```bash
python -m hokduck.build --stage all
```

18 コアで約 9 分、ピークメモリ約 2.0 GB、できあがりは 310 MB です。最後に
`sql/90_verify.sql` の 37 個の検査が走り、1 つでも失敗するとビルドは成功を
名乗らずに終わります。検査だけを既存のファイルに掛けることもできます。

```bash
python -m hokduck.verify --db jra3q_hokkaido_wind_2016-2025_v1.duckdb
```

## 中身の見当

```
dim_timebin  24 行   月の前半・後半で区切った時期ビン
dim_level    38 行   1000--1 hPa の気圧面
dim_grid    570 行   0.375 度格子（ガウス格子なので緯度は不等間隔）

fact_wind        519,840 行   統計量 34 変数
fact_speed_fit 1,559,520 行   風速の分布 3 族（正規・Weibull・一様）
fact_dir_fit   1,559,520 行   風向の分布 3 族（von Mises・巻き付け正規・円周一様）
```

最初に試すなら次の 2 つです。

```sql
SELECT * FROM nearest_cell(42.506, 143.440);        -- 最寄り格子点
SELECT * FROM fits_at(42.506, 143.440, 10, 2);      -- 10 月後半の分布 38 面ぶん
```

## 開発

```bash
pytest tests -q              # 単体テストと、同梱のデータベースに対する検査
pytest tests -q -m slow      # 上流パイプラインとの照合（上の 2 つが揃っている場合のみ）
ruff check .
```
