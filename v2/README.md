# 日本全国 高層風 統計データベース v2

JRA-3Q 再解析の 2016--2025 年から、日本全国の上空の風を集計した DuckDB ファイル
`jra3q_japan_wind_2016-2025_v2.duckdb` です。北海道版（`research/hokkaido_duckdb`、v1）と
同じ表の形で、範囲を日本全国に広げました。

> `LICENSE-DATA.md`、または `SELECT * FROM v_license` を見てください。

## 範囲

| 項目 | 値 |
|---|---|
| 範囲 | 北緯 24.0--46.0 度、東経 122.0--146.5 度（与那国・波照間〜稚内・根室、小笠原を含む） |
| 格子 | 0.375 度（約 40 km）、3,953 点。海上と近隣国の点も含む |
| 高さ | 38 気圧面（1000--3 hPa、地上〜約 40 km） |
| 時期 | 24 の半月ビン（各月の 1--15 日と 16 日--月末） |
| 期間 | 2016--2025 年、6 時間ごと（14,610 解析） |

沖ノ鳥島（北緯 20 度）と南鳥島（東経 154 度）は範囲の外です。

## 中身

```
dim_timebin            24 行   月の前半・後半で区切った時期ビン
dim_level              38 行   1000--3 hPa の気圧面
dim_grid            3,953 行   0.375 度格子（59 × 67、ガウス格子なので緯度は不等間隔）

fact_wind       3,605,136 行   統計量 34 変数
fact_speed_fit 10,815,408 行   風速の分布 3 族（正規・Weibull・一様）
fact_dir_fit   10,815,408 行   風向の分布 3 族（von Mises・巻き付け正規・円周一様）
fact_wind_diurnal 7,589,760 行 解析時刻別（300 hPa より下の 20 面）
fact_drift         94,872 行   標準の飛行条件での落下位置
fact_wind_rose     87,552 行   風配図（代表 1 格子点）

ファイルの大きさ 約 2.0 GB
```

v1 と同じく、風速には 3 族（正規・Weibull・一様）、風向には 3 族（von Mises・巻き付け正規・
円周一様）の分布を当てはめてあり、関数形と定数が表に入っています。風配図（`fact_wind_rose`）は
領域中央の 1 格子点（北緯 35.03 度、東経 134.25 度、兵庫県西部）だけです。

最初に試すなら次の 2 つです。

```sql
SELECT * FROM nearest_cell(35.681, 139.767);      -- 東京の最寄り格子点
SELECT * FROM fits_at(26.212, 127.679, 1, 1);     -- 那覇、1 月前半の分布 38 面ぶん
```

表と列の意味、取扱上の注意（ガウス格子なので `lat = 35.0` は 0 行を返す、AIC の差は
n/n_eff だけ水増しされている、など）は利用手引 `docs/` にまとめてあります。
列の説明はデータベースの中にも入っています。

```sql
SELECT * FROM v_column_dictionary;
```

## 利用手引（Sphinx）

`docs/` は Sphinx の手引で、HTML と PDF（`docs/japan-wind-duckdb.pdf`、約 107 ページ）を
作れます。SQL の例はビルドのたびに実際のデータベースで実行し、結果の表を埋め込むので、
手引の数字とデータベースの中身がずれません。

```bash
cd v2/docs
pip install -r requirements.txt       # sphinx, furo, duckdb（図には matplotlib も要る）
make                                  # 図 → doctest → HTML → PDF（警告があれば止まる）
make html                             # HTML だけ → _build/html/index.html
```

PDF には LuaLaTeX と日本語フォント（原ノ味）が要ります。章は次のとおりです。

| 章 | 内容 |
|---|---|
| データベースが初めてなら | SQL と DuckDB の最低限 |
| まず動かす | 最寄り格子点、鉛直プロファイル、全国の地点を並べる、分布を引く |
| データの構造 | 次元表とファクト表、時期ビン、高度、風向の向き |
| 取扱上の注意 | ガウス格子、ΔAIC の水増し、一様分布が勝った 263 面など |
| データの図一覧 | 潮岬と全国の図 11 枚 |
| 分布の定義 | 風速 3 族・風向 3 族の式と scipy での再現 |
| 使い方の例 | 時期を選ぶ、分布から標本を作る、風配図、落下位置 |
| 表と列の一覧／用語集／再現の手順／ライセンス | 参照用 |

## 確かめたこと

- ビルドの検査 37 個がすべて通る（行数・主キーの重複・値の範囲・マクロが動くこと。
  稚内・大樹町・東京・潮岬・那覇・与那国・父島で最寄り格子点が 30 km 以内に見つかること）。
- 北海道版 v1 と重なる 408 格子点（372,096 行）で、平均風速・p90・定常度・有効標本数が
  完全に一致し、分布の当てはめの差は 7×10⁻¹⁵ 以下、選ばれた族も全部一致する。
- `check_figures.py` の地図（`check/`）を目で確認した。1 月の 200 hPa のジェットの芯は
  北緯 30--35 度、7 月後半の 10 hPa は全域で東風、飛行距離は 1--2 月の北緯 30--33 度で最長。
- 風速の分布で一様分布が選ばれる面が 263 面（全体の 0.007 %）ある。10--12 月のジェットの
  高さ（150--225 hPa）で、朝鮮半島から日本海・東シナ海にかけて出る。ジェットの芯が南北に
  動いて風速の分布が平らになるためで、88 % は次点と区別できない（`is_ambiguous`）。

## 作り直す

```bash
cd research
python -m windclim.cli fetch --box jp               # JRA-3Q、約 100 分、8 GB
python -m windclim.cli aggregate --region japan     # 約 15 分、ピーク 8.6 GB
cd ../v2
PYTHONPATH=.:../research python -m jpduck.build --stage all   # 18 コアで約 40 分、ピーク 6.9 GB
PYTHONPATH=.:../research python -m jpduck.verify              # 検査だけ
PYTHONPATH=.:../research python check_figures.py              # 確認用の地図 → check/
```

ビルドの最後に `sql/90_verify.sql` の検査（37 個）が走り、1 つでも失敗すると
ビルドは成功を名乗らずに終わります。行数の検査は v1 のように数値を書き込まず、
次元表の行数から計算します。
