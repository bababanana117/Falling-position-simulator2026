統計モード (気候値モード)
============================

統計モードとは
----------------

統計モードは、打ち上げ日時がTawhiriの予報窓(現在から−12時間〜+7日、
``frontend/src/time/forecastWindow.ts`` の ``FORECAST_PAST_MS`` /
``FORECAST_FUTURE_MS``)より先のときに使われる機能である。Tawhiriは
GFS数値気象モデルの予報期間を超える日時には応答できないため、その代わりに
2016年から2025年までの統計的な風データ(JRA-3Q再解析データから作成)を使い、
その時期にありがちな落下点の分布と、平均的な軌道を示す。

.. important::

   統計モードは **天気予報ではない**。過去10年分のその時期(半月単位)の
   風の統計から「だいたいこの範囲に落ちる」という傾向を示すものであり、
   打ち上げ日の実際の天気を反映しない。

いつ使われるか
----------------

``frontend/src/time/forecastWindow.ts`` の ``classifyLaunchTime()`` が
打ち上げ日時を次の3つに分類する。

.. list-table::
   :header-rows: 1

   * - 分類
     - 条件
     - 動作
   * - ``forecast``
     - 現在−12時間 〜 現在+7日
     - Tawhiri APIで通常の予測を行う
   * - ``climatology``
     - 現在+7日より先
     - バックエンドが設定されていれば統計モード、無ければエラー
   * - ``error``
     - 現在−12時間より過去
     - エラー表示 (気象モデルの範囲外)

さらに ``resolveLaunchMode()`` が、バックエンドが有効かどうか
(``VITE_API_BASE`` が設定されているか、``frontend/src/api/backend.ts`` の
``backendEnabled()``)を見て、``climatology`` 判定でもバックエンドが無い
場合はエラーに変える。本番向けのビルド(``.github/workflows/deploy.yml``)
では ``VITE_API_BASE`` が ``https://api.cusf2026.ddd3h.com`` に設定されて
いるため(:doc:`deployment`)、本番では統計モードが有効になる。

統計モードは単発予測とモンテカルロの両方で使える。時系列予測・最適化・
感度分析は統計モードに対応していない(予報窓を超えた時刻は単に無視される)。

画面に表示されるもの
------------------------

統計モードで予測を実行すると、``frontend/src/components/ScenarioInfo.tsx``
に次の帯(バナー)が表示される。

.. code-block:: text

   統計モード（気候値・1月前半、JRA-3Q 2016–2025 年）— 予報ではありません
   使った格子点: 42.70, 143.20（12 km）/ 層どうしの相関 ρ = 0.45

地図には以下が描画される。

- **平均の軌道**: バックエンドが返す ``trajectory`` (30秒刻みの上昇・降下
  の点列)を、単発予測と同じ飛行経路として描画する
- **落下点の標本**: バックエンドが2次元正規分布から引いた標本点
  (既定500、最大2000)を、通常のモンテカルロの着地点群と同じ描画経路
  (信頼楕円・ヒートマップ・安全判定)で表示する
- **50/90/95%信頼楕円**: 標本からフロントエンド側で計算する
  (``frontend/src/stats/landing.ts``、通常のモンテカルロと同じ関数)

計算方法の概要
----------------

統計モードの計算はバックエンド(``backend/bfps/climatology/``)で行う。
詳しい設計は
``docs/superpowers/specs/2026-10-12-climatology-mode-design.md`` に
まとまっている。ここではその要点を示す。

1. 打ち上げの日時(UTC)をJSTに直し、月と半月ビン(1〜15日が前半、16日以降
   が後半、年は使わない)を決める。打ち上げ地点に最も近い格子点を探す
   (``store.nearest_cell()``)。最寄り格子点が60kmより遠い場合は、
   統計データの対象外としてエラー(HTTP 422)になる
2. その格子点・時期の38気圧面について、隣の面との中点で区切った層ごとに、
   上昇速度・破裂高度・降下速度(海面換算)から「その層に何秒いるか」
   (:math:`T_k`)を計算する
3. 平均的な流され方は、各層の平均風ベクトル :math:`(\bar{u}_k, \bar{v}_k)`
   と :math:`T_k` の積を足し合わせたものになる。

   .. math::

      \bar{E} = \sum_k T_k \bar{u}_k, \qquad \bar{N} = \sum_k T_k \bar{v}_k

4. 散らばり(共分散)は、層ごとの風の共分散行列 :math:`\Sigma_k` と、
   層どうしの相関 :math:`\rho` から次の式で求める。

   .. math::

      \Sigma = (1-\rho) \sum_k T_k^2 \Sigma_k + \rho\, M M^\top,
      \qquad M = \sum_k T_k L_k

   ここで :math:`L_k` は :math:`\Sigma_k` の対称な平方根(固有値分解による)
   である。:math:`\rho = 0` なら層どうしの風が完全に独立、:math:`\rho = 1`
   なら完全に連動している場合に相当する
5. :math:`\rho` は、同じ格子点・時期の実際の飛行記録(``fact_drift``、上昇
   5m/s・破裂高度30km・降下6m/sの標準的な飛行での落下点の分散)を再現
   するように解く。東西方向と南北方向でそれぞれ解いた値の平均を使う
6. 平均 :math:`(\bar{E}, \bar{N})`、共分散 :math:`\Sigma` の2次元正規分布
   から、指定した個数の標本を乱数(指定したシード)で引き、緯度経度に変換
   する
7. 平均の軌道は、30秒刻みで上昇・降下させながら、その時点の位置の最寄り
   格子点・その高度の層の平均風で進めて作る。この軌道の着地点は3の平均
   落下点とは厳密には一致しない(位置による風の違いを反映するため)が、
   実データでの検証ではそのずれは0.4〜3.3km程度で、落下点の散らばり
   (30〜74km)に比べて十分小さい

限界
----

- **予報ではない**。その時期(半月)に実際にどんな天気になるかは反映しない
- **半月単位の気候値**\ である。年による違い(エルニーニョ等)は平均の中に
  埋もれる
- 降下は地表の標高ではなく常に海面(0m)まで計算する。実際の着地点が内陸
  なら、統計モードの降下距離・時間は実際より長くなる
- モンテカルロの試行回数は、バックエンド自体は最大2000まで受け付けるが、
  UI側は通常モードと同じ上限500に制限している。これはOpen-Meteo
  Elevation APIの1分あたりのリクエスト数制限に合わせたもので
  (:doc:`known_issues`)、統計モードの計算そのものの上限ではない
- 使用データはJRA-3Q(気象庁)の2016年から2025年の再解析データから作成した
  派生データであり、ライセンスは CC BY-NC-SA 4.0 (非商用)である。
  この派生データ自体はGitリポジトリには含まれていない

API
---

``POST /api/climatology/predict`` (``backend/bfps/api/routes_climatology.py``)

リクエスト:

.. list-table::
   :header-rows: 1

   * - フィールド
     - 型
     - 説明
   * - ``launch_latitude`` / ``launch_longitude``
     - float
     - 打ち上げ地点
   * - ``launch_altitude``
     - float
     - 打ち上げ高度 [m]、既定0
   * - ``launch_datetime``
     - datetime
     - 打ち上げ日時 (UTC)
   * - ``ascent_rate``
     - float
     - 上昇速度 [m/s]、0.5〜15
   * - ``burst_altitude``
     - float
     - 破裂高度 [m]、1000〜45000
   * - ``descent_rate``
     - float
     - 降下速度(海面換算) [m/s]、1〜30
   * - ``n_samples``
     - int
     - 標本数、10〜2000(既定500)
   * - ``seed``
     - int または null
     - 乱数シード(既定42)

レスポンス:

.. list-table::
   :header-rows: 1

   * - フィールド
     - 説明
   * - ``timebin``
     - ``{month, bin, label, period}``。例: ``label="1月前半"``、
       ``period="2016–2025"``
   * - ``cell``
     - 使った格子点の緯度経度と、打ち上げ地点からの距離 [km]
   * - ``mean_landing``
     - 平均落下点の緯度経度(参考値。地図には描画しない)
   * - ``covariance_m2``
     - 落下点の共分散行列 ``[[東西, 東西×南北], [東西×南北, 南北]]`` [m²]
   * - ``rho``
     - 解いた層間相関 :math:`\rho`
   * - ``samples``
     - 標本の緯度経度のリスト
   * - ``trajectory``
     - 平均の軌道の点列 ``{latitude, longitude, altitude, time_s}``
   * - ``burst_index``
     - ``trajectory`` のうち破裂点のインデックス
   * - ``flight_time_s``
     - 飛行時間 [秒]
   * - ``warnings``
     - 警告文字列の配列 (例: 破裂高度が統計データの最上層より上にある場合)

エラー:

- 統計データベースのファイルが見つからない、または開けない: HTTP 503
- 打ち上げ地点が統計データの範囲外 (最寄り格子点が60kmより遠い): HTTP 422
- 破裂高度が統計データの最上層 (3hPa、約40km) より上: エラーにはせず
  ``warnings`` に記載し、それ以上の高度では最上層の風で代用する
